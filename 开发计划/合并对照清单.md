# Pond × Bekkan 合并对照清单

> 2026-08-02 建。本文是合并工程的对照基准：决策记录、模块处置、op 映射、语义差异、已知问题。
> 原则：**本阶段只做模块合并与项目重组，不修 bug**；发现的 bug 记入第 5 节，统一后续处理。

---

## 1. 决策记录（已与双方确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 包名 / Blender 版本 | 包名 `pond_bekkan`；整体**锁定 Blender 5.2**，不带入 Pond 的 4.2 兼容分支 |
| 2 | 冲突实现的选型原则 | **以更有效的实现为准**。执行核查后发现父子级两边大多语义不同（见第 4 节更正），实际仅「选择父级」存在真冲突，采用 Pond 实现；后续同类冲突同样按此原则 |
| 3 | Analyzer / AddonManager 归属 | **只在别馆模式显示**（工程分析目前是实验性功能）；蛙灾模式保持 Pond 原貌，别馆模式保持 Bekkan 原貌，仅底层合并 |
| 4 | 合体版默认模式 | **蛙灾模式** |
| 5 | 快照分割线交互 | 先用 Bekkan 实现（快照在线左、Alt+右键拖）；**Pond 的交互代码保留为注释**，日后可能要做到两个模式两套交互 |

补充决策（执行中细化）：

- 合并后采用扁平布局：**仓库根目录即插件包根目录**（用户已确认并删除 `Bekkan/`、`Pond/` 旧目录，历史见 git 合并前 commit）；开发时把整个仓库文件夹复制/链接进 addons 即是合体版。
- 一个插件包只能有一个 AddonPreferences：合并为根级 `prefs.py` 一个类，内含「模式切换（仅合体版）+ Pond 模块开关 + 颈椎拯救者设置」，`bl_idname = __package__` 动态获取。
- `AddonManager/preferences.py` 中硬编码的 `bl_idname = "bekkan_visn"` 必须改为动态（原写法在合体包下会失效）。
- Analyzer 的 Operator/PropertyGroup 在 core 常驻注册（`scene.analyzer_props` 的标记数据随 .blend 保存，模式切换不能丢）；只有它的**面板**随别馆模式注册/注销。
- 快照快捷键两项目原本一致（Ctrl+Alt+右键拍、Alt+右键拖），合并后由 core 统一注册一次，两个模式通用。

## 2. 目标结构（已按扁平化调整：仓库根 = 插件包根）

```

├── prefs.py                # 唯一的 AddonPreferences（模式 + Pond模块开关 + 颈椎拯救者设置）

│   ├── snapshot.py  hierarchy.py  stage.py  anime.py  render_preset.py  texture.py
│   ├── organize.py  lumen.py  synccheck.py  c4d_bridge.py  preset_lib.py  version.py
│   ├── palette.py  trace2solid.py  sixproj.py  lightdesk.py  bakemap.py  splitter.py
│   ├── renderlayers.py
│   ├── analyzer/           # model / state / checks / fixes / ops / props（ui 拆到 ui/bekkan）
│   └── addonmanager/       # common / properties / operators / prefs_access（ui/preferences 拆出）
├── ui/
│   ├── __init__.py         # 按当前模式 register/unregister，提供 apply_mode()
│   ├── bekkan/             # 别馆模式：快照面板 + 工具箱5面板 + 工程分析面板 + 颈椎拯救者面板

├── tools/   开发计划/       # 仓库文件，不进 zip
└── dist/                   # 打包产物
```

## 4. 父子级 op 映射与语义差异（合并基准表 · 已按真实源码更正）

> **执行期更正**：初版（基于子代理报告）误判两边功能一一等价。逐行核对真实源码后发现
> **大部分 op 语义不同**，并非同一功能的两种实现。除「选择父级」外全部保留、忠实移植。

| 功能 | Pond | Bekkan | 真实语义对比 → 处置 |
|---|---|---|---|
| 打组 | `pond.group_to_parent` / `pond.group_each`（挂到**激活物体**下） | `object.parent_to_empty_visn` / `..._individual`（**新建空物体**包裹） | 语义不同 → **全部保留** |
| 选择父级 | `pond.select_parents` | `object.select_parent_visn` | 语义等价 → **采用 Pond 实现**，Bekkan 版废弃，别馆面板按钮重接到 `pond.select_parents` |
| 释放 | `pond.release_up`（**自己**升到祖父级） | `object.release_all_children_to_subparent_visn`（**孩子**释放给上级） | 语义不同 → **全部保留** |
| 拎出 | `pond.extract`（保子树摘自己） | `object.solo_pick_visn`（孩子先释放给上级、再摘自己） | 语义不同 → **全部保留** |
| 拎出并删除 | `pond.extract_delete`（删**原父级链**） | `object.solo_pick_delete_visn`（删**所选物体自己**） | 语义完全相反 → **全部保留** |
| 迁移动画 | —（Pond 无） | `object.parent_to_empty_anim_visn` | 保留，忠实移植（fcurve 深拷贝方案） |
| 对焦物体 | —（Pond 无） | `camera.create_focus_object` | 保留，忠实移植（含外围遮黑） |

**bl_idname 规则**：语义等价被取代的才废弃（本次仅 `object.select_parent_visn` 一个）；
其余 Bekkan op 保留原 `_visn` / `camera.*` / `wm.*` idname，Pond op 保留 `pond.*`。
注意：`core/hierarchy.py` 的 `centro`/`centro_global` 是**选中物体原点位置均值**（Bekkan 原版语义），
StageOps 依赖它，勿改成包围盒中心。

## 6. 打包规格（dist 三版本）

| 版本 | zip 根目录（=包名） | bl_info 名称 | `_build_mode.py` | 行为 |
|---|---|---|---|---|
| 合体版 | `pond_bekkan` | `PondBekkan` | `combined` | 偏好设置面板有「蛙灾模式 / 别馆模式」二选一开关，默认蛙灾 |
| 蛙灾独立版 | `Pond` | `池塘 Pond` | `pond` | 无开关，打开即是 Pond 原 UI；包名沿用 `Pond`，她的旧偏好设置（模块开关）可继承 |
| 别馆独立版 | `bekkan_visn` | `Bekkan_visn` | `bekkan` | 无开关，打开即是 Bekkan 原 UI；包名沿用 `bekkan_visn`，直接替换旧安装 |

三版同一份源码，打包脚本 `build.py` 负责：复制源码 → 写入对应 `_build_mode.py` → 补丁 bl_info 名称 → 产出 zip 到 `dist/`。
