  用 `ops._sync_findings` 同步 findings 进列表，draw 才有真实行数据。
- T4 `test_uilist_draw_item_signature`：D7 回归，`inspect.signature` 校验 `draw_item` 含 `flt_flag`。
- T5 `test_uilist_draw_item_runs`：D7 补充，mock 调 `draw_item` 不崩 + 行内图标合法。

—— 注意无 `property` 形参（曾记错，已修）。

### 3.2 `core/analyzer/checks.py`
- 新增 `collect_merge_same_material_groups(min_count=10)`：返回 `[[obj,...],...]`，
  check 与 fix 共用（仿 `collect_duplicate_material_groups` 模式）。
- `check_merge_same_material` 改为复用该公共函数。
- 新增 `collect_identical_duplicate_groups()`：返回 `[[keep_mesh, dup_mesh, ...],...]`，
  check 与 fix 共用。
- `check_identical_duplicates` 改为复用该公共函数（删了内联的 `mesh_objs` 分组，
  改用 `collect` + 外层 mesh 名→对象名索引）。

### 3.3 `core/analyzer/fixes.py`（新增两个 fix）
- `fix_merge_same_material(context, item)`：
  用 `collect_merge_same_material_groups` 重新分组（不依赖 check 运行时状态），
  每组 `bpy.ops.object.join()` 合并到第一个。多用户网格先 `data.copy()` 单用户化。
  只操作当前 View Layer 可访问对象。返回 `(fixed, skipped, info)`，info 含 `made_single`/`groups`。
- `fix_identical_duplicates(context, item)`：
  用 `collect_identical_duplicate_groups` 重新分组，每组 keep=第一个 mesh，
  引用其余 mesh 的对象 `obj.data = keep`（关联复制）。形态键保底再验一遍。
  旧 mesh 若 users 归 0 不自动删，info 里报告 `orphan_meshes` 提示留待 Purge。

### 3.4 `core/analyzer/ops.py`
- `ANALYZER_OT_fix.execute` 加两个分支：`STRUCT.merge_same_material` → `fix_merge_same_material`、
  `STRUCT.identical_duplicates` → `fix_identical_duplicates`，修复后自动 `run_visn` 重扫。
- 新增 `_build_markdown(context, props)`：把 findings 渲染成 Markdown（标题+元信息+统计+
  按影响分组的清单，标记状态 □/✓/×）。
- 新增 `ANALYZER_OT_export_report`（`analyzer.export_report_visn`）：
  `invoke` 弹 `fileselect_add` 文件保存对话框，`execute` 写 .md。

### 3.5 `core/analyzer/__init__.py`
- `_CLASSES` 加 `ANALYZER_OT_export_report`。

### 3.6 `ui/bekkan/analyzer_panel.py`
- `_draw_fix_buttons` 加两个按钮：`STRUCT.merge_same_material`（icon=JOIN）、
  `STRUCT.identical_duplicates`（icon=LINKED）。

## 5. 蛙灾侧 analyzer 入口：三方案（待蛙灾自选，暂不实施）

蛙灾（Pond）侧目前没有 analyzer 入口。若后续她需要把工程分析暴露到池塘 UI，
有三种放法（按推荐度排）。**动手前须由蛙灾确认，因涉 Pond 专属 UI 区**：

### 方案 A（推荐）：复用别馆面板类
蛙灾侧新建 `ui/pond/panels/analyzer.py`，直接 `import` 别馆的
`VIEW3D_PT_analyze_visn` + `ANALYZER_UL_finding`，只改 `bl_category='池塘'`、
`bl_parent_id`（挂某个抽屉）、`poll` 用蛙灾的 `module_enabled('show_analyzer')`。
正文零副本。两模式不同时注册，`bl_idname` 不冲突。
- 优点：最省事，正文天然唯一，改 UI 只动别馆版一处。
- 缺点：蛙灾面板 import 别馆模块，跨了归属边界（但只读不改，可接受）。
- 需在 `ui/pond/prefs.py` 的 `MODULES` 加 `("show_analyzer", "工程分析")`；
  根 prefs.py 两个 `MODULES` 都有 `show_analyzer` 时，第二个循环覆盖第一个的
  `BoolProperty` 注解——同 key 同类型，覆盖无害。

### 方案 B：新增第五抽屉「📋 分析」
`ui/pond/sections.py` 加 `POND_PT_sec_analyze`（`bl_order=4`），analyzer 面板挂它下面。
- 优点：与别馆侧「工程分析」对等、醒目。
- 缺点：池塘原有四抽屉语义变了，需同步更新 README/CLAUDE.md 的抽屉描述。

### 方案 C：挂「📦 交付」抽屉下
不新增抽屉，`bl_parent_id='POND_PT_sec_ship'`。
- 优点：不动抽屉结构，改动最小。
- 缺点：「交付」语义偏输出，分析偏诊断，略不贴。

**推荐方案 A**——复用面板类，正文零副本，与上轮的「analyzer 独立版面板 build 时生成」
思路一脉相承（都是正文唯一源）。
