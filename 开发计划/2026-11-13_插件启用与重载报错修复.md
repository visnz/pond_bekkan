# 插件启用与重载报错修复

## 目标与范围

用户报告插件重载失败：`core/unselectable.register()` 读取 `bpy.data.objects` 时得到 `_RestrictData`，随后 `core/debug.py` 的无参错误回调收到异常参数，产生第二个 TypeError。
本次修复两个 New 模块，保留 Bounds/Textured 联动；新增相关测试与开发记录。不修改 Mixed 注册中心、注册顺序或模式分发，未改动此前 setup 等工作区修改。
沿用本会话读取的个人插件开发技能和项目规范。

## 原因与修改

- Blender 5.2.4 的 `addon_utils.enable()` 在 `RestrictBlend` 内调用插件 `register()`，期间不能读场景对象。之前直接调用 `addon.register()` 的后台回归及局部 UI 注册测试没有覆盖这一条件。
- `core/unselectable.py`：注册阶段只创建属性、操作符、订阅、处理器和一次性计时器。`_initial_display_sync()` 在注册结束后同步已有禁选对象；暂时仍受限则 0.1 秒后重试。`_sync_display_modes()` 遇到受限数据返回 False，刷新视图也对不可用的 window_manager 做保护。注销会取消未完成的首次同步计时器。
- `core/debug.py`：`on_error(exc=None)` 接受 `addon_utils` 传来的异常，并保留异常回溯；兼容没有参数的调用。启用与注销失败都不会再被回调签名错误掩盖。
- `tools/test_addon_enable.py`：新增真实 `addon_utils.enable()` 注册回归、受限环境同步重试、同步前立即禁用、连续两次磁盘重载、偏好保留、旧计时器/处理器清理，以及启用/注销失败回调检查。
- `tools/test_unselectable.py`：适配首次同步延后，并检查注销时计时器被清理。
- `开发计划/模块归属标注.md`：更新两个 New 模块说明，无需改共同维护清单。

## 调试过程

修复前使用独立 factory-startup 实例运行新增启用测试，复现与用户完全相同的 `_RestrictData.objects` 异常。修复后该流程成功。
读取本机 `addon_utils.py`，核对 RestrictBlend 注册边界和 `handle_error(ex)` 的实际调用签名。
随后在独立 Blender 窗口用真实事件循环验证首次同步计时器与 `wm.reload_pond_bekkan_visn` 操作符的延迟回调，连续两次重载均成功。一次性窗口脚本位于忽略目录 `temp/`。
没有重载、修改或保存用户当前 Blender 工程；测试实例已退出。

## 验证结果

- 修复前 `tools/test_addon_enable.py` 失败，错误为 `_RestrictData` 没有 objects。
- 修复后 `tools/test_addon_enable.py` 通过：真实启用、禁用、受限重试、两次磁盘重载、模式/模块偏好保留、原始异常报告及监听清理。
- `tools/test_unselectable.py` 完整回归通过，Bounds/Textured、点击激活、原有过滤和保护行为保持正常。
- 独立窗口计时器验证通过：首次自动同步为 Bounds，两次操作符延迟重载、激活 Textured、锁回 Bounds、最后禁用与清理均通过。
- 本次 Python 文件语法检查与 `git diff --check` 通过。
