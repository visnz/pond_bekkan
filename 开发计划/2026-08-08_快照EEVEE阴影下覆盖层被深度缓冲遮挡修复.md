# 2026-08-08 快照在某些工程里"看起来没反应"——EEVEE 阴影下覆盖层被深度缓冲遮挡

## 目标

用户反馈：某个朋友的工程里，视口着色切到「渲染」（Rendered）+ EEVEE 后拍快照，
卡顿几秒后像没反应一样——不报错、不花屏/纯黑、没有残留旧画面、不卡死，但快照列表
确实新增了一条正常格式的记录。纯空白 EEVEE 测试工程、以及把该工程内容导入新工程
（渲染设置归零）后都能正常复现快照对比，说明问题出在该工程 Scene 级渲染设置上，
不在物体/材质数据本身。

## 排查过程

1. 用户确认「快照导出」到图像查看器能正常看到拍到的内容——**证实截图本身完全
   正常，问题只在"实时对比覆盖层显示"这一步**，把范围从 `_capture_offscreen`
   收窄到 `_draw()`。
2. **第一版假设（已推翻）**：怀疑 EEVEE Next 视口合成器（`space.shading.
   use_compositor`）在覆盖层之后又画了一层东西盖住。用户实测确认合成器是
   Disabled，假设不成立。
3. 用户继续实测提供新证据：
   - 材质预览视图下（这份问题工程里）快照同样没出现——说明不是 Rendered 专属，
     真正的触发条件跟"是否在算真实场景阴影"有关，而不是着色模式的标签本身。
   - 把渲染采样里的「阴影」（Shadow）关掉后，快照**出现了**，拖动滑块正常，
     但形容是"好像被藏在了最下面那样"——不是干净地恢复正常，是部分/间歇性可见。

## 根因假设

`core/snapshot.py::_draw()`（`SpaceView3D` 上 `"WINDOW"`/`"POST_PIXEL"` 绘制
回调）画对比覆盖层这段代码，只设置了 `gpu.state.blend_set("ALPHA")`（透明混合），
**全文件没有任何地方调用 `gpu.state.depth_test_set(...)` 关闭深度测试**。

POST_PIXEL 类回调按约定应该画纯 2D 屏幕空间内容、永远盖在 3D 场景之上，这要求
深度测试必须是关闭的（`'NONE'`），否则屏幕空间四边形会被拿去跟当前深度缓冲比较。
Wireframe/Solid/Material Preview（无场景灯光时）这些传统着色路径，Blender 一直会
把深度测试状态恢复成关闭再交给 POST_PIXEL 回调；EEVEE Next 的真实阴影计算管线
（无论是不是叫"Rendered"，只要视口在算真实场景阴影）内部有大量需要深度信息的
通道，如果它没有把深度测试状态干净地复原成关闭，我们的覆盖层四边形就会被当成
场景几何体去跟遗留深度缓冲比较——深度缓冲里"更远"的区域覆盖层被挡住，只有恰好
"更近"或深度缓冲本身没有内容的区域才画得出来，跟"藏在最下面"的描述一致；关掉
阴影后走更简单的渲染路径，巧合地让状态复原正常，所以多半能看见，但因为根因是
"状态没显式设置、听天由命"，效果不稳定。

不能 100% 确认具体是不是 EEVEE 阴影管线残留的深度状态，但不管上游具体是哪个
状态没复原，给覆盖层显式关闭深度测试都是正确且没有副作用的防御性修复。

## 改动（`core/snapshot.py`，Mixed 共同维护文件）

跨边界说明：只在 `_draw()` 里加一行 GPU 状态设置，不改绘制内容/截图逻辑；两个
模式共用同一份 `_draw()` 实现，行为同步变化——对原来就能正常显示覆盖层的场景是
无操作性质的防御性加固，没有可见差异；只有"覆盖层曾被场景深度缓冲挡住"的场景会
变化（从看不见/部分看见变成正常可见）。不需要更新 `模块归属标注.md`。

在 `blend_set("ALPHA")` 之前显式加：

```python
gpu.state.depth_test_set("NONE")
```

函数末尾不需要额外恢复——`_draw` 是 POST_PIXEL 回调里最后画的内容，且 Blender
每次重绘都会重新准备绘制状态，跟现有 `blend_set("ALPHA")`/`blend_set("NONE")`
只在需要处 set、不保存/恢复旧状态的处理方式一致。

未跑 GUI 实测，只过了 `python -m compileall -q .`。是基于代码审查 + 用户提供的
现象证据链推出的最佳假设，不是 100% 确认过的根因。需要用户在那份问题工程里实测：

- Rendered 视口着色、阴影保持开启（不用再关阴影这个变通方案）下拍摄，确认对比
  覆盖层（快照内容 + 白色分割线 + 右上角文字角标）完整可见，不再"藏在下面"。
- 材质预览视图下同样验证一遍（这份工程材质预览也曾经不正常）。
- 确认线框/实体等原本就正常的模式加了这行之后依旧正常（不应该有任何变化）。
- 如果这行改完仍然没有完全解决（比如覆盖层还是间歇性被挡住），说明除了深度
  测试之外可能还有别的 GPU 状态（比如 depth mask、stencil test）也需要显式复位，
  需要用户反馈具体还剩下什么现象再继续加。
