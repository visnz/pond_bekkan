# 2026-08-06 · 聚焦对象创建位置修复

## 1. 目标

`CAMERA_OT_create_focus_object`（`camera.create_focus_object`，🏗 搭建类 →「创建对焦对象」按钮）
原实现会把焦点空物体创建到**当前选中/活跃物体**下，而不是场景摄像机上。修复为：
先激活并选中当前活跃摄像机，再在它的基础上运行创建脚本。

## 2. 改动内容

文件：`core/hierarchy.py`（Mixed 模块内 **Bekkan 专属函数**，改动不涉及 Pond 代码）。

`execute` 里 `cam.data.passepartout_alpha = 1.0` 之后，把原来的

```python
focus.select_set(True)
bpy.ops.object.parent_no_inverse_set(keep_transform=True)
focus.select_set(False)
```

改为先取消现有选中、激活并选中场景摄像机，再执行同一个父子操作：

```python
for obj in context.selected_objects:
    obj.select_set(False)
context.view_layer.objects.active = cam
cam.select_set(True)
focus.select_set(True)
bpy.ops.object.parent_no_inverse_set(keep_transform=True)
focus.select_set(False)
```

## 3. 根因

`bpy.ops.object.parent_no_inverse_set` 的语义是：把**所有选中物**绑定到**当前活跃物体**上。
原代码只选中了 `focus`，活跃物体仍是用户点按钮时正选中的那个物体，于是：

1. `focus.parent = cam` 被该操作覆盖，焦点空物被绑到了错误物体上；
2. 若用户点按钮时还选着别的物体，那些物体也会被一并重新绑定到活跃物体下。

## 4. 验证

- `python -m compileall -q core/hierarchy.py` → exit 0。
- 逻辑核对：deselect 全部 → active=cam → 选中 cam+focus → parent_no_inverse_set 只把
  focus 绑到 cam（cam 是 active 不会被自我绑定）；操作后 focus 取消选中、cam 保持
  激活+选中（符合「激活并选中当前活跃摄像机」的要求）。

## 5. 影响范围 / 归属

- Mixed 模块 `core/hierarchy.py` 内 Bekkan 专属函数 `CAMERA_OT_create_focus_object`
  （见 `模块归属标注.md`），改动局部于此操作符，不影响 Pond 侧任何 op / 面板。
- 按钮只在别馆 `ui/bekkan/panels.py`（🏗 搭建类）出现，蛙灾侧无此入口 → 对另一模式
  无 UI/行为影响。归属标注无需更新（函数仍为 Bekkan 维护）。
- 已向当前用户（桶桶）说明并获明确指示后修改。
