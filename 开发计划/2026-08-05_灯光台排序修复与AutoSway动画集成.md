# 2026-08-05 工具箱面板微调、渲染预设采样数修复、灯光台排序修复与 AutoSway 动画集成

## 目标

1. 把「创建聚焦对象」从「👪 上下级」挪到「🏗 搭建类」面板下面。
2. 「创建预设」弹窗只留两个路径字段，分辨率/采样数/帧范围/步长都不展示，自动读取当前场景值；
   顺带修复采样数读取只认 Cycles、EEVEE 下读错的 bug。
3. 灯光台面板默认排在颈椎拯救者上面，颈椎拯救者保持最下面（它切出来的第三方面板也跟着落到最下面）。
4. 把独立插件 `autosway.py`（骨骼摆动驱动器工具）整合进「🎞 动画类」面板，收进小三角折叠子面板，不用时不占篇幅。

## 改动

### 0. `ui/bekkan/panels.py`：创建聚焦对象搬家

`camera.create_focus_object` 按钮从 `VIEW3D_PT_parents_visn`（👪 上下级）移到
`VIEW3D_PT_stage_visn`（🏗 搭建类）draw() 末尾，纯挪位置，逻辑不变。

### 0.1 `core/render_preset.py`：`RENDER_OT_create_presets` 采样数 bug 修复 + 弹窗精简

- `invoke()` 原来用 `hasattr(context.scene, 'cycles')` 判断该读哪个引擎的采样数——
  但 `scene.cycles`/`scene.eevee` 是常驻 PointerProperty，不管当前引擎是什么都存在，
  `hasattr` 永远为真，导致 EEVEE 场景也一直在读 Cycles 的采样值。改成看
  `scene.render.engine` 字符串（`.endswith('CYCLES')` / `'EEVEE' in engine`），
  跟 `core/analyzer/checks.py::_engine()` 的既有写法一致。
- `draw()` 弹窗原来展示分辨率 X/Y、采样数、帧范围、帧步长四组可编辑项，现在全部删掉，
  只留绝对路径/相对路径两个字段——这四项在 `invoke()` 里已经自动从当前场景读取
  （帧步长维持默认值 1），不需要用户在弹窗里再看一遍或改。

### 1. `ui/bekkan/lightdesk_panel.py`

`BEKKAN_PT_lightdesk` 子类化 `POND_PT_lightdesk` 只改了 `bl_parent_id`（顶层面板），
没改 `bl_order`——继承了 Pond 那边为 `POND_PT_sec_look` 子面板排序用的 `bl_order = 3`，
导致灯光台在别馆顶层面板里排到最后（连颈椎拯救者都在它前面）。别馆其它顶层面板都没设
`bl_order`（默认 0），补一行 `bl_order = 0` 清零即可，靠注册顺序回到 `ui/bekkan/__init__.py`
注释里写的原意（灯光台在颈椎拯救者之前）。

### 2. `core/anime.py` + `ui/bekkan/panels.py`：AutoSway 集成

来源：`C:\Users\yue.zhao04\AppData\Roaming\Blender Foundation\Blender\5.2\scripts\addons\autosway.py`
（独立插件，不在本仓库内，只搬功能，不改原文件）。

- 逻辑层（`PropertyGroup` + 8 个 Operator）平移进 `core/anime.py`，`scene.autosway_settings`
  跟其它常驻场景属性同规格注册；`anime` 模块本来就在 core 常驻注册表里，两模式都注册，
  不用改 `core/__init__.py`。
- 面板层新增 `VIEW3D_PT_anime_autosway_visn`，`bl_parent_id = "VIEW3D_PT_anime_visn"` +
  `bl_options = {'DEFAULT_CLOSED'}`，挂在「🎞 动画类」下面，默认折叠成小三角。
- **未**沿用原插件的 `bl_context = "posemode"`（那样非姿态模式下整个子面板直接消失，
  折叠三角展开后空空如也，容易让人以为面板丢了）。改成始终可展开，`draw()` 里判断
  `context.mode != 'POSE'` 时只显示一行提示「需要在姿态模式(Pose Mode)下使用」，姿态模式下
  才画出完整内容——这是本次按用户要求做的调整，与原插件行为不同。
- 保留原插件 `autosway.*` 操作符前缀（自成一套工具，不与项目既有 `pond.*`/`camera.*`/
  `analyzer.*` 等命名空间冲突）。

## 已知风险 / 待验证

- **与独立插件共存冲突**：如果 Blender 里还启用着独立的 `autosway.py`，两边都会注册
  同一批 `autosway.*` 操作符 idname 和 `Scene.autosway_settings`，后注册的会覆盖前者，
  可能导致行为不确定。**建议整合完成后在 Blender 偏好里禁用/卸载独立版**，没有跟用户
  当场确认，GUI 实测时留意。
- 未跑 GUI 实测，只过了 `python -m compileall -q .`。需要 F8 重载后核对：
  - 别馆侧栏「🎞 动画类」下出现折叠的「AutoSway（骨骼摆动）」子面板；
  - 姿态模式选中骨骼后能正常「添加摆动」「清除动画」「控制组管理」；
  - 侧栏面板顺序：灯光台在颈椎拯救者之前，颈椎拯救者仍在最下面；
  - 「创建聚焦对象」按钮出现在「🏗 搭建类」而不是「👪 上下级」；
  - EEVEE 场景下「创建预设」弹窗只有两个路径字段，采样数按 EEVEE 的值而非 Cycles 的值生成。
