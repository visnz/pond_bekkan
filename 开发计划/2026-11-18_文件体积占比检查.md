# 文件体积占比检查

## 目标与范围

在别馆「搭建类」新增提交前文件体积检查，统计图片、几何等占比，并列出大数据及可检查的清理线索。
本轮修改 `core/file_size_audit.py`（New）、`core/__init__.py`（New 注册分发）、
`ui/bekkan/panels.py`（Bekkan 工具箱），不修改 Mixed 或 Pond 专属模块。
同步 `模块归属标注.md`，共同维护索引不变。

## 统计口径

只读磁盘上最后一次保存的当前 .blend，不另存副本、不调用 pack、不清理或重载用户工程。
尚未保存时提示先保存。压缩文件显示实际磁盘大小，但分类占比按压缩前数据量展示，
不会将压缩前体积误称为压缩后精确占用。

使用 Blender 自带 `_blendfile_header` 与 `blend_render_info.RawBlendFileReader`，
支持新 17 字节文件头、旧文件头、Zstandard 和 gzip。
按 ID 数据块及其后续 DATA 块实际写入字节分类，包含块头及文件结构，分类和与总字节数校验一致。
保存文件自身 SDNA 决定 ID 名称偏移，兼容长名称，不硬编码名称位置。
大块数据流式跳过，只保留小 ID 前缀和 SDNA，不读取贴图像素或复制几何数据。

分类为：贴图/图片、几何/形态键、材质/节点/世界、动画/骨架、场景/对象/集合、其他/工作区/文件结构。
几何统计包含已保存的拓扑、UV、属性、形态键等；共享 Mesh 只计一份，独立复制的数据分别计入。
形态键数据独立列入几何排名。外部图片的记录本身计入文件，但外部像素文件不虚增到 .blend 占比。

当前引用数、保留标记、同路径图片重复、网格顶点/面/UV/属性及共享对象数附加在排名中，
与最后保存的文件体积明确区分；未保存改动时醒目提醒。
外部图片页按规范化路径去重，列文件大小及缺失情况；UDIM、序列、影片标注未统计整套大小。

## 界面与操作

- 搭建类「检查文件体积占比」，旁边的信息按钮可重新打开上次报告。
- 报告五个页签：占比概览、贴图、几何、其他数据、外部图片。
- 概览用进度条及百分比/体积展示；明细按体积降序，每页八项。
- 点击 Mesh 名称选择当前视图层使用它的可见、可选对象，不解除隐藏或禁选。
- 结果存在模块级缓存与弹窗快照，不将大报告写入用户 .blend。

## 调试与验证

Blender 5.2.4 LTS 和 5.3.0 隔离后台测试通过：
真实未压缩文件字节等于磁盘大小、分类合计及百分比合计、压缩/gzip 解析、旧 4.05 资源解析；
打包与外部图片区分、同路径重复图片、缺失图片、共享及独立 Mesh、长中文名称、形态键、其他 Scene 内容；
检查不改文件时间/体积/选择/活跃对象、几何定位、截断文件拒绝、模式切换及启用注销。

首轮调试修正等待光标 API（属于 Window，非 WindowManager）和报告操作器 RNA 注册名检测。
后台 Python 直接赋值不会自动置 `bpy.data.is_dirty`，未保存状态测试加入原生 undo_push；
保存会将图片路径相对化，测试预期统一通过 bpy.path.abspath 解析。
GUI 测试加载隔离后台样例后需等待窗口及侧栏重绘，再设活动类别。

所有测试使用独立 BLENDER_USER_RESOURCES 与 factory-startup；保存仅涉及 temp 下的独立样例。
临时样例写入出现 Blender 缩略图缓存提示，文件读取和统计成功，不涉及本功能写入行为。
脚本：`tools/test_file_size_audit.py`、`tools/test_file_size_audit_ui.py`。

两版本真实 GUI 测试通过：检查入口、五个报告页实际绘制、其他数据第二页、几何定位和上次报告重新打开。
截图已检查，未出现 draw 异常；验证报告操作不改变对象/图片/Mesh 数据块数量或 dirty 状态。
日志在 `temp/file-size52.log`、`temp/file-size53.log`，GUI 结果及截图位于 `temp/file-size-ui52/`、`temp/file-size-ui53/`。
静态语法检查与差异格式检查通过，四种 zip 已重新打包，三个完整版本收录新模块，工程分析独立版范围不变。

## 后续与限制

当前报告针对最后保存文件；修改并保存后手动重新检查。
不分析跨帧变化，不估算外部缓存、整个 UDIM/序列集合、链接库依赖包的总体积。
压缩流无法精确分摊压缩后每种数据的字节量，报告明确采用压缩前占比。
本轮未 commit/push。
