# 2026-10-20 新增「棋盘格陈列」（搭建类）

## 目标

用户需求：选中一批物体后，把它们以棋盘格网格形式重新摆开，以激活物体为
中心，用于整理/逐个查看，不改变物体朝向和自身相对高度关系。

## 分支

`feature/checkerboard-layout`（从 `bekkanDEV` @ `1048ead` 切出）。
注：切分支前先把 `bekkanDEV` 上未完成的「单体迁移动画到上级 5.2 Action API
修复」WIP 挪到了独立分支 `fix/hierarchy-anim-migrate-5.2api`，让
`bekkanDEV` 回到干净状态。

## 跨边界说明

`core/stage.py` 是 Mixed 共同维护文件，但本次只是新增一个独立 operator 类
（`StageCheckerboardLayout`），未修改文件内任何已有函数/类的实现，不影响
Pond 侧摄像机组/约束灯光等既有功能与 UI。只在 `ui/bekkan/panels.py` 的
「🏗 搭建类」面板加一个按钮，不碰 Pond 面板。已在 `模块归属标注.md` 的
`core/stage.py` 明细表追加一行，标记为 New。

## 改动

- `core/stage.py`：
  - 新增 `_world_bbox(obj)`：取世界空间包围盒，返回 `(max_span, bottom_z)`。
    无网格数据的物体（空物体等）`bound_box` 退化为 8 个重合的原点，
    `max_span=0`，不用特判。
  - 新增 `_checkerboard_warnings(objs)`：纯函数，返回警告文案列表（物体数
    超 100 / 尺寸最大最小比超 100 倍），拆成纯函数方便脱离 UI 单测。
  - 新增 `StageCheckerboardLayout` operator
    （`object.checkerboard_layout_visn`）：
    - `poll`：有选中物体且有激活物体。
    - `invoke`：先确认激活物体在选中范围内（否则 report ERROR +
      CANCELLED），算警告；有警告则 `invoke_props_dialog` 弹窗展示（仿照
      `core/analyzer/ops.py` 的 `ANALYZER_OT_fix.invoke/draw` 写法），点
      「确定」才真正执行；无警告直接 `execute`。
    - `execute`：按 `ceil(sqrt(n))` 定边长 `grid`，中心格取 `(grid//2,
      grid//2)`，其余格子按到中心格的切比雪夫距离（环层）→欧式距离→行列号
      排序展开，取前 n-1 个按物体名称排序依次分配（保证每次运行结果一致）；
      格子边长 = 所选物体中最大 `max_span` × `margin`（`FloatProperty`，
      默认 1.2，暴露在 F6 重做面板）；高度处理为「底部对齐」——以激活物体
      当前的 `bottom_z` 作为地面高度，每个物体保留自己原点到包围盒底部的
      局部偏移量，只改 `matrix_world.translation`，不碰旋转/缩放；不改变
      原有选中集合；最后用 `core/sixproj.py` 里已有的
      `temp_override(area, region)` 写法找到一个 `VIEW_3D` 区域执行
      `view3d.view_selected()`。
- `ui/bekkan/panels.py`：`VIEW3D_PT_stage_visn.draw()` 追加
  `col.operator("object.checkerboard_layout_visn", icon='MESH_GRID')`。
- `开发计划/模块归属标注.md`：`core/stage.py` 明细表追加一行。

## 调试与测试过程

用户当前 Blender（5.2.2 LTS）已通过 MCP for Blender 直接连接且插件已在
`addons_core` 下以开发模式启用，所以没有用 `--background` 探针脚本，而是
直接在真实 Blender 会话里用 `execute_blender_code` 跑端到端验证：

1. `python -m compileall -q core/stage.py ui/bekkan/panels.py`：无报错。
2. 确认 `MESH_GRID` 是 5.2 合法图标枚举（`UILayout.bl_rna` 里查到）。
3. `bpy.ops.script.reload()` 热重载后确认
   `bpy.ops.object.checkerboard_layout_visn` 已注册、`poll()` 行为正确
   （无选中→False，有选中+active→True）。
4. 13 个随机位置的 1×1×1 立方体，全选、指定其中一个为 active，直接调用
   operator：
   - `report`：「已将 13 个物体陈列为 4×4 棋盘格」，`grid=4` 符合
     `ceil(sqrt(13))=4` 预期。
   - 激活物体位置原地不动；其余物体落在以 `cell_size=1.2`（`max_span=1.0 ×
     margin=1.2`）为格距、按环层展开的网格坐标上，坐标偏移量与手算一致。
5. 构造一个"底部不在原点"的物体（1×1×4 立方体，原点在几何中心，
   `bottom_z=-5`，原点到底部局部偏移 `+2`）+ 一个空物体（零尺寸）+ 一个
   正常立方体作 active：陈列后验证每个物体的「原点到自身底部的局部偏移」
   保持不变，且所有物体的"底部"落在同一个世界高度（= active 的
   `bottom_z`）——落地对齐逻辑正确。
6. `_checkerboard_warnings`：
   - 构造尺寸相差 150 倍的两个物体 → 正确识别「超过 100 倍」。
   - 构造 101 个物体 → 同时触发数量警告与尺寸警告（因为其中仍包含
     150 倍差异的两个物体）。
7. `poll()` 边界：无选中返回 `False`；激活物体不在选中范围内时调用
   operator，`invoke` 正确抛出 `RuntimeError`，错误信息为「激活物体必须在
   选中范围内」，不会往下执行到网格计算。
8. 测试后清空场景只留一个默认立方体，截图确认视口正常，无残留测试物体。

## 测试结果

- 静态检查通过。
- 真实 Blender 5.2.2 环境端到端功能测试全部通过（网格尺寸、环层排序、
  底部对齐、两类警告判定、poll/active 校验分支）。
- 未做的测试：
  - **弹窗交互本身**（`invoke_props_dialog` 点击「确定」/「取消」的真实
    GUI 行为）——这次是用 `execute_blender_code` 直接调用 operator，天然
    绕过了弹窗的鼠标交互，和仓库里其它 `invoke_props_dialog`/
    `invoke_confirm` 功能的开发日志惯例一样，这部分需要用户在真实 GUI 里
    点一下按钮确认体验是否顺手。
  - 面板按钮在「别馆」N 面板「🏗 搭建类」抽屉里的实际点击/图标显示效果，
    建议用户下次打开 Blender N 面板时顺手看一眼。

## 已知限制 / TODO

- `grid` 为偶数时没有严格几何中心格，取 `(grid//2, grid//2)` 近似居中，
  对"整理查看"场景够用，不追求像素级对称。
- 目前只支持陈列到世界水平面（按用户确认的方案），不支持朝向当前视角的
  平面；如果以后需要"always face viewport"的陈列方式，需要另外设计（会
  随视角转动变化，且依赖调用时的视口状态，复杂度和维护成本都更高，所以
  这次按用户选择先不做）。
- 没有对隐藏物体（`hide_get()`）或链接实例（linked duplicates，共享同一
  `object.data`）做特殊处理；多个物体共享同一份网格数据时，移动
  `matrix_world.translation` 互不影响，行为符合预期，未发现问题。
