# 2026-08-04 · analyzer 检查项基础调优（补齐「一键」承诺）

## 1. 目标与范围

用户要求「先做基础调优，按照预想的功能完善」，再由用户在 Blender 里逐条测试。

逐条核对 `core/analyzer/checks.py` 的评级字段（`EASE_ONE`=一键 / `EASE_HALF`=半自动 /
`EASE_HARD`=复杂）与 `ui/bekkan/analyzer_panel.py` 的 `_draw_fix_buttons()` 实际覆盖，
发现 9 条 `EASE_ONE` 里有 6 条完全没有修复通道，详情面板只会落到「暂无可用的自动修复」，
评级与实际功能不符。本轮补齐这 6 条，并顺手补了 5 条 `EASE_HALF`（这些检查的 `suggestion`
文本已经写明了具体数值/开关，属于最容易补的「半自动」部分）。

全部改动限定在 Bekkan 专属模块：`core/analyzer/fixes.py`、`core/analyzer/ops.py`、
`ui/bekkan/analyzer_panel.py`。未改 `core/stage.py`（Mixed），只调用其中已有的
`object.delete_empty_null_visn` op。

**不做**：`RENDER.resolution`、`DATA.unused_shapekeys`、`TRANS.tiny_scale`/`big_scale`、
`MAT.images_per_material`、`GEOM.high_poly_count` 等——这些没有「安全的默认修复值」
（分辨率改多少、形态键删不删、缩放多少算对，都是创作判断），维持手动。

## 2. 补的修复（Tier 1：EASE_ONE 缺口）

| key | 新 fix 函数 | 做法 |
|---|---|---|
| `STRUCT.empty_objects` | `fix_empty_objects` | 调用已有 `object.delete_empty_null_visn()`，用调用前后 EMPTY 总数差算 fixed |
| `STRUCT.orphan_objects` | `fix_link_orphans` | 移入新集合 `_未分类孤立对象`（非破坏性，不删数据） |
| `DATA.unused_actions` | 无新函数 | 并入既有 `elif` 分支（`DATA.unused_materials`/`DATA.orphans`/`DATA.unused_actions`），复用 `fix_purge_unused` |
| `RENDER.persistent_data` | `fix_toggle_persistent_data` | 直接取反 `use_persistent_data`（check 只在两种错误方向触发，取反即修正） |
| `RENDER.motion_blur` | `fix_disable_motion_blur` | `use_motion_blur = False` |
| `EEVEE.shadows` | `fix_shadow_pool` | `eevee.shadow_pool_size = '2048'` |

## 3. 顺手补的修复（Tier 2：EASE_HALF 快速优化）

| key | 新 fix 函数 | 做法 |
|---|---|---|
| `RENDER.device` | `fix_device_gpu` | `cycles.device = 'GPU'`（check 触发时已确认有可用 GPU） |
| `RENDER.bounces` | `fix_cap_bounces` | Cycles 钳制 max/diffuse/glossy/transmission/volume bounces + 关焦散；EEVEE 钳制光追 `resolution_scale` |
| `RENDER.output_format` | `fix_output_compression` | PNG compression 0→15；EXR codec NONE→ZIP（不改动格式本身，合成/序列器切格式仍留手动） |
| `RENDER.sampling` | `fix_adaptive_sampling` | 仅 Cycles：开自适应采样 + 阈值抬到 0.05；EEVEE 返回「需按画面手动权衡」 |
| `RENDER.light_count` | `fix_light_perf_toggles` | 仅 Cycles：开 `use_light_tree` + `use_shadow_culling`；EEVEE 无对应属性，返回提示 |

## 4. 调试记录

- **`fix_link_orphans` 不能用 View Layer 过滤**：其它 fix 惯例是先算
  `_view_layer_objects(context)` 再过滤，但孤立对象定义上就是「不属于任何集合」，
  天然不在任何 View Layer 里——套用惯例会导致这条 fix 永远啥都不修。改为直接核对
  `obj.users_collection` 是否仍为空。
- **`fix_empty_objects` 计数方式**：`delete_empty_null_visn` op 内部逻辑比 check 的简单过滤
  更复杂（含集合实例保护 + 递归深度判断），op 的 self.report 不返回结构化数据，
  用调用前后 `bpy.data.objects` 里 EMPTY 总数差值代替，比重新套用 check 的过滤条件更准确。
- **EEVEE `ray_tracing_options.resolution_scale`**：沿用 `checks._as_int()` 而非自己重写数值
  防御，避免与 check 侧判断口径不一致。
