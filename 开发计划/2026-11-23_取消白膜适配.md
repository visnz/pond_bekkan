# 取消白膜适配

## 目标与范围

用户要求增加白膜适配的相反操作：把原本接入 Cycles 专属输出的连接全部断开，
把 EEVEE 输出改回 All。与白膜适配一样覆盖全部物体材质与 World。

已对照项目开发规范、合并清单和模块归属。
修改 Bekkan 的 core/texture.py 和 New 的 ui/bekkan/light_compose_panel.py；
无需新增面板或修改 Mixed 注册入口，池塘界面不变。
保留 2026-11-20 白膜接口扩展与 World 适配尚未提交的改动。

## 实现与修改文件

- core/texture.py：cancel_cycles_clay() 统一处理材质/World，新增
  material.cancel_cycles_clay_visn（UNDO）；在本模块注册列表加入操作器。
- ui/bekkan/light_compose_panel.py：在适配按钮下方追加「取消白膜适配」。
- tools/test_cancel_cycles_clay.py：断线、输出选择、重复执行及实际渲染验证。
- tools/test_cycles_clay_ui.py：扩展原 GUI 测试，覆盖取消、一次撤销/重做和重复取消。
- 本日志、模块归属标注；重新生成四种发行 zip。

断开所有 Cycles 专属输出的全部输入，包括 Surface、Volume、Displacement、Thickness，
无论上游是白膜还是自定义着色器；仅 Cycles 的材质/World 也按用户要求断线。
保留上游节点、共享组、图片、原 EEVEE 连线、节点位置及其他节点间连接。
不可编辑数据块或没有相应输出的数据跳过。
多个 EEVEE 输出时，原活跃 EEVEE 输出改为活跃 All，其他输出同样改 All。
报告分别统计材质和 World 的修改数、断线数、恢复 All 数及跳过数。

## 调试与输出归属

首轮仅关闭 Cycles 输出的 is_active_output，后台探测发现专属 target 仍优先于 All，
不能保证恢复原材质。因此断开的 Cycles 输出也改为非活跃 All，并设置
bekkan_cancelled_cycles_output 标记，使原材质真正接管两种引擎。

再次执行适配前，_restore_cancelled_cycles_outputs() 将仍为空的标记输出恢复成 Cycles，
复用输出节点。取消后用户手动接线或改归属的输出保留其修改，并清除过时标记。
重复取消不再改动；不会删除输出节点或恢复已断开的自定义 Cycles 材质连接。

## 验证

Blender 5.2.4 LTS / 5.3.0 隔离后台均通过：

- 材质和 World 全部 Cycles 输入断线，原连接、节点数量/位置保持。
- 原 EEVEE 转活跃 All，两种引擎选到原输出；多个 EEVEE 和已有 All 的选择正确。
- 仅 Cycles 数据断线、空树跳过、重复取消无新增修改。
- 注册/注销、入口位于适配按钮下方、图标有效。
- 再次适配复用原输出节点；取消后手动接线不会被空输出恢复逻辑覆盖。

两个版本 Cycles 96×96 原材质、白膜、取消后对比渲染通过：
白膜与原图显著不同；取消后与原图最大像素差 0.0。
两个版本真实 GUI 灯光合成按钮绘制、World/物体输出显示，
取消的原生一次撤销/重做（含输出目标、连接和标记）及重复取消通过，截图已检查。

使用 factory-startup 独立实例和临时配置，没有重载、保存或修改用户当前工程。
后台日志在 temp/cancel-clay52.log、temp/cancel-clay53.log；
GUI 结果和截图在 temp/clay-ui52/、temp/clay-ui53/。

静态语法及 git diff --check 通过。
