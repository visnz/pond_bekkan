# 绑定动画：左右肢体姿态镜像交换

## 目标与范围

- 别馆侧在「搭建类」后新增独立「🦴 绑定动画」面板，首批两个按钮：左右手姿态交换、左右腿姿态交换。
- 对当前活动骨架的当前姿态做 X 轴水平镜像交换。双手包含肩膀、手臂、手腕、手指、IK/FK 控制；双腿包含腿根、脚、趾与中间的胯部/hips 控制。
- 支持普通骨架与 Rigify。只改当前姿态及用户当前自动关键帧设置所触发的关键帧，不改 Rest Pose、权重或约束结构。

## 修改

- `core/anime.py`：新操作符 `pose.swap_limb_pose_visn`。Blender 可识别的 `.L/.R`、`Left/Right` 左右命名使用原生姿态缓冲区的 flipped 粘贴，包含控制骨自定义属性；中文/日文 `左/右` 命名使用骨架空间 X 镜像矩阵交换。Rigify 跳过 DEF/MCH/ORG/VIS 及不可选的 IK target 机制骨。
- `ui/bekkan/panels.py`：增加「绑定动画」面板及两个按钮。
- `ui/bekkan/prefs.py`：增加面板开关。
- `开发计划/模块归属标注.md`：更新别馆模块归属说明。未修改共同维护模块或蛙灾侧 UI。

## 调试与测试

- 首次纯骨架小样发现旋转测试骨未切到 Euler 模式，修正测试后确认原生 flipped 粘贴确实交换并镜像旋转、位置及 IK/FK 自定义属性；中间 `hips` 自身镜像。
- 独立 Blender 5.2.3 测试普通骨架和模拟 Rigify 命名骨架：肩膀、手 IK、腿 IK、hips、中文左右骨骼姿态及原选择状态均通过；手按钮不改腿，腿按钮不改手。
- 独立 Blender 5.2.3 启用 Rigify 并生成实际 human rig（706 根骨骼）：识别手部 76、腿部 31 根可选控制骨，两个按钮均执行成功。初次选择范围包含每侧的 `_ik_target` 内部骨（原生粘贴实际跳过），已从目标中过滤。生成前遇到 addon_utils 直接启用未建立偏好记录，改用 Blender 的 `preferences.addon_enable` 后通过。
- Python 语法检查与 `git diff --check` 通过；机制骨过滤调整后，普通骨架与模拟 Rigify 测试再次通过。

## 后续观察

- Rigify 的约束、隐藏控制和自动关键帧组合较多，需在用户真实角色上检查最终变形。脚本不自动插关键帧；原生姿态粘贴会遵循 Blender 当前自动关键帧设置。
- 原生姿态复制会覆盖 Blender 会话里的单一姿态缓冲区。非常规左右命名若不含 `左/右` 且 Blender 也不识别，按钮会提示没有找到成对骨骼。
