# 2026-08-27 单体迁移动画到上级：Blender 5.2 分层 Action API 崩溃修复

## 目标

用户反馈：在一个带动画的物体上运行"单体迁移动画 到上级"
（`object.parent_to_empty_anim_visn`），报错：

```
File "...\core\hierarchy.py", line 476, in execute
    for src_fc in src_action.fcurves:
AttributeError: 'Action' object has no attribute 'fcurves'
```

现象：上级空物体已创建，但因为崩溃在动画迁移这一步中途炸掉，物体没有被
重新挂到上级下（父子关系没建立），动画也没迁移过去。

## 根因

Blender 5.2 把 Action 改成了分层结构（layers → strips → channelbag），
`Action.fcurves` / `Action.groups` 这种旧的直接访问方式被完全移除。
`core/hierarchy.py::P2E_anim_migrate.execute()` 里复制动画的代码还是照抄
旧 API（`src_action.fcurves`、`dst_action.fcurves.new(...)`），在 5.2 环境下
必然崩溃。

## 排查（`--factory-startup --background` 探针脚本，跳过第三方插件后秒级验证）

1. `hasattr(action, "fcurves")` → `False`，确认旧 API 已彻底移除。
2. 读侧确认可行模式：
   ```python
   for layer in action.layers:
       for strip in layer.strips:
           if strip.type != 'KEYFRAME':
               continue
           cb = strip.channelbag(slot)   # slot = animation_data.action_slot
           if cb:
               fcurves.extend(cb.fcurves)
   ```
3. 写侧 `Action.fcurve_ensure_for_datablock(datablock, data_path, index)`：
   必须先把目标 action 赋给 `datablock.animation_data.action`，再调用这个
   方法才不报错；调用后会自动创建/绑定对应的 `ActionSlot`，不需要手动处理。
   顺序反了会报 `RuntimeError('Invalid Input Error: Assign action ... before
   calling this function')`。
4. `fcurve.group = 另一个 action 里的 group`（想在复制时保留 Graph Editor
   分组）：**不报错，但静默失效**——赋值后读回来是 `None`。所以决定完全不
   迁移分组信息，避免误清空自动创建的分组却什么好处都没有。
5. 端到端 write→readback 验证：关键帧数据（co）复制后能通过目标物体自己的
   action_slot 正确读回，数值完全一致。

## 改动（`core/hierarchy.py`，Mixed 共同维护文件）

跨边界说明：只重写 `P2E_anim_migrate.execute()` 里"复制动画"这一段的内部
实现（读写 fcurve 换成 5.2 分层 API），不改函数签名、不改上级空物体创建/
重新挂父级这两段逻辑、不改 idname/label/poll。两个模式共用同一份
`core/hierarchy.py`，行为同步修复——这是纯粹的崩溃修复，不是设计变更，
不影响另一模式的 UI/行为。不需要更新 `模块归属标注.md`。

具体改动：
- 读取源 fcurve 列表：从 `src_action.fcurves` 改成
  `src_action.layers → layer.strips → strip.channelbag(src_slot).fcurves`
  （`src_slot = ad.action_slot`）。
- 创建目标 fcurve：从 `dst_action.fcurves.new(data_path=..., index=...,
  action_group=...)` 改成 `dst_action.fcurve_ensure_for_datablock(empty,
  data_path, index=...)`，并把 `empty.animation_data_create()` +
  `empty.animation_data.action = dst_action` 的赋值**提前到复制循环之前**
  （原代码是循环结束后才赋值，5.2 下顺序反了会报错）。
- 去掉 `fcurve.group` 相关的分组复制逻辑（原因见排查第 4 点）。
- 关键帧字段（co / handle / handle_type / interpolation / type）与
  fcurve 修饰器复制逻辑保持不变。
- `migrated` 计数器与最后的 `self.report(...)` 提示逻辑保持不变。

## 测试结果

- `python -m compileall -q .`：无报错。
- `--factory-startup --background` 端到端脚本测试（创建带 2 个关键帧的
  动画物体，用 `context.temp_override` 模拟单选后调用操作符）：
  - 不再崩溃，`operator result: {'FINISHED'}`。
  - `obj.parent` 正确指向新建的上级空物体。
  - `obj.location` 归零，`obj.animation_data` 被清空（`None`）。
  - 上级空物体的 action 里能读到迁移后的 fcurve，关键帧数值
    `(1.0, 1.0)` / `(20.0, 5.0)` 与源数据完全一致。
- 未做 GUI 实测（背景脚本测试用 `temp_override` 绕过了真实的选中/UI 上下
  文），需要用户在 Blender 里对真实带动画的物体跑一遍确认：
  - 上级空物体正确创建并挂好父子关系；
  - 原物体动画完全消失，改由上级空物体驱动，播放动画时物体世界位置/
    旋转/缩放视觉上与迁移前一致；
  - 有 fcurve 修饰器（如 Cycles/Noise）的曲线，修饰器参数也正确带过去了。
