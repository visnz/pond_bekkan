# 一键 setup 工作区

## 目标与授权范围

- 在 3D View → 别馆 → 搭建类增加「一键 setup 工作区」，集中执行用户每次新工程的初始化步骤，分步骤组织以便后续扩展。
- 用户明确选择「清空当前场景对象，再创建这套 setup」，随后追加「检查并启用 Rigify，在世界原点创建 Human 骨架」。
- 继续按用户技能库 `blender/addon-development/SKILL.md`、项目 AGENTS.md、合并对照清单与模块归属标注实施。
- 新建 `core/workspace_setup.py`（New），在 `core/__init__.py`（New）追加注册，在 `ui/bekkan/panels.py`（Bekkan）追加入口。未修改 Mixed 的 `stage.py` / `hierarchy.py` 或模式分发，直接调用既有操作器；未修改 Pond UI，共同维护清单不变。
- 保留上一项 Shader 无关节点筛选的改动，与本功能一同整理提交。

## 实现内容

| 步骤 | 设置或行为 |
|---|---|
| Eevee | 开启视口抖动阴影、光线追踪，光追分辨率 1:1；High Quality Normals；Shadow Pool 2 GB、Volume Pool 1 GB |
| Cycles | Device = GPU；开启视口自适应采样，Noise Threshold = 0.02；开启视口去噪，复制渲染去噪的算法、通道、预过滤、质量和 GPU 选项；Persistent Data 开启 |
| 共享设置 | Compositor Device = GPU；View = ACES 2.0；File Working Space = ACEScg |
| 渲染器 | 两套参数直接写入各自 RNA，最终始终保留运行前的 engine；不改系统 GPU 后端偏好 |
| 输出 | 30 fps，fps_base = 1；PNG，`//output/output.png`，与用户指定的 Windows 路径 `//output\output.png` 等效 |
| 世界 | 新建独立 World，Sky Texture → Background → World Output，避免改动其他场景共用的世界节点 |
| 物体 | 世界原点 2m Box；选择 Box 调用 C-P 摄像机组，将新相机设为场景相机，再调用创建对焦对象 |
| 灯光 | 选择 Box 调用中心约束灯光，将新灯改为 Sun、强度 10，保留原脚本的父级与约束行为 |
| Rigify | 检查 Human 元骨架操作器；未启用时从已安装模块找到并启用 Rigify；添加完整 Human 元骨架（本机 159 根骨骼），对象世界变换归零、缩放为 1 |
| 外部数据 | `bpy.data.use_autopack = True`，与 Automatically Pack Resources 开关一致 |

各新对象收进独立 Setup 集合，完成后选中 Box。成功后解除当前场景旧根对象和旧集合入口，覆盖隐藏、禁选及排除对象，不全局删除其他场景或集合实例仍在使用的数据。不自动清理孤立数据。

## 文件与函数

- `core/workspace_setup.py`：`render_settings_plan()`、`create_sky_world()`、`create_setup_objects()`、`setup_workspace()`；Rigify 检测与注册操作器。
- `core/__init__.py`：追加模块导入和 `_MODULES` 项，保持既有顺序。
- `ui/bekkan/panels.py`：`VIEW3D_PT_stage_visn.draw()` 顶部追加按钮。
- `tools/test_workspace_setup.py`：后台参数、对象、共享场景保护、重复初始化与故障恢复测试。
- `tools/test_workspace_setup_ui.py`：一次性原生图形实例中的按钮、完整初始化、撤销/重做和相机视图重复执行测试。
- `开发计划/模块归属标注.md`：更新模块功能描述及新增模块归属。

## 调试与验证

1. 查询 Blender 5.2.4 LTS 的实际 RNA 和自带 UI 源码，确认光追枚举为 `'1'`，池容量枚举为 `'2048'` / `'1024'`，File Working Space 使用 `wm.set_working_color_space(working_space='ACEScg', convert_colors=True)`。实测 SETTINGS 图标合法。
2. 确认本机已安装 Rigify，启用后可调用 `object.armature_human_metarig_add`。首次回归发现缺失操作器的 `get_rna_type()` 会抛 `KeyError`，补充该异常后启用流程通过。
3. 后台测试通过：全部参数、去噪五项同步、8 个对象的类型/约束/父级、159 骨 Human、原点变换、天空连线、隐藏/禁选/排除对象清场，以及共享集合在另一场景保留。
4. 依次从 Cycles / Eevee / Workbench 执行，均保留原渲染器；重复执行后当前场景始终为 8 个对象。
5. 注入创建天空失败，确认原场景入口、相机、世界和设置恢复，本次新建对象与数据清理，无半套 setup 留下。
6. 独立图形测试通过：搭建面板按钮实际绘制；一次撤销恢复原场景、输出和工作色彩空间，重做恢复 setup；相机视图中再次执行成功。检查了截图 `temp/workspace_setup_ready.png`、结果 JSON 和 stderr，无本功能异常。已有 SnapPanel 命名、其他插件缺少 bl_info 以及绘制耗时提示未改动。
7. 发现 Blender 原生的 `use_autopack` 文件开关不进入场景撤销栈；测试和说明明确其保持开启。Rigify 启用属于插件偏好状态，同样不会随场景撤销。
8. Python 编译与 `git diff --check` 通过。测试均使用 factory-startup 独立实例，未修改、重载或保存用户当前工程，未显式保存用户偏好。

## 边界与后续

- 按钮在 3D 视图物体模式下可用；局部视图需先退出，以保证创建与清场范围明确。
- 缺失 Rigify 安装时会在清场前停止并提示；本脚本不联网安装插件，也不生成最终控制 rig，仅添加 Human 元骨架。
- ACEScg 是整个 `.blend` 的 File Working Space，调用官方转换会转换文件内已有颜色数据。
- 自动打包与 Rigify 启用不会随场景撤销；其余已测试的场景/渲染设置支持撤销与重做。
- 当前需求已完成；未来新步骤可继续加入对应函数，不必改原始相机/灯光脚本。
